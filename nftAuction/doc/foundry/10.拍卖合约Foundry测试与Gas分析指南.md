## 4. 生成 Gas 报告

在项目根目录执行：

```bash
forge test --gas-report
```

运行结束后，终端会输出每个函数的 gas 消耗表，包括：

- 部署合约的 gas  
- 每个外部函数（例如 `createAuction`、`bidWithETH`、`bidWithERC20`、`endAuction`）的平均/最大 gas  

> 如果只关心某个合约，可以结合 `--match-contract` / `--match-test` 限制范围：

```bash
forge test --match-contract NftAuctionWithOracleUpgradeableTest --gas-report
```

## 5. 如何阅读和分析测试结果

1. **是否存在 “Failing tests”**  
   - 有失败用例时，优先根据报错信息（revert reason / assert 失败）定位逻辑 bug。  
2. **拍卖流程核心检查点**（在 `NftAuctionWithOracleUpgradeable.t.sol` 中）  
   - `createAuction` 后 NFT 拥有者是否变为拍卖合约；  
   - `bidWithETH` / `bidWithERC20`：  
     - 出价不足是否 `Bid below minimum` 直接回退；  
     - 出价不超过当前最高价是否 `Bid too low` 回退；  
     - 更高出价是否正确覆盖 `highestBidder` / `highestBid`；  
   - `endAuction`：  
     - 竞拍结束后 NFT 是否归中标者；  
     - 卖家是否收到对应 ETH 或 ERC20 资金。  
3. **Gas 优化方向**（结合 Gas 报告）  
   - 重点关注频繁调用函数：`createAuction`、`bidWithETH`、`bidWithERC20`、`endAuction`；  
   - 典型可优化点：  
     - 将重复读取的 `storage` 变量先缓存为 `memory` 局部变量；  
     - 减少不必要的事件参数、`require` 文本（错误字符串）长度；  
     - 尝试把不会变化的参数做成 `immutable`（仅在非可升级合约中适用）。

## 6. 发现潜在 Bug 的思路示例

你可以基于当前测试进一步扩展，寻找逻辑漏洞，例如：

- **边界条件**  
  - `duration = 0`、`minBidUSD = 0` 是否已经正确 `revert`（当前代码已通过 `require` 防御）；  
  - `endAuction` 在没有任何出价的情况下是否会把 NFT 还给卖家（已在测试中覆盖）。  
- **价格预言机问题**  
  - 使用 `MockPriceFeed.updatePrice` 模拟价格突然下降/上升，检查出价逻辑是否仍然合理；  
  - 将 `stalePriceThreshold` 设为较小值，构造过期价格的场景，确保 `PriceOracleLib` 的 `getPriceInUSD` 会按预期 `revert`。  
- **安全性**  
  - 通过 `vm.startPrank` 模拟恶意用户多次出价、取消等行为，验证不会产生资金卡死或可被盗取的情况。
