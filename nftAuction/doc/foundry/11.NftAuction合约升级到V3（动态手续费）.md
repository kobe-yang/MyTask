## 1. 升级背景与目标

- 当前合约版本：
  - `NftAuctionWithOracleUpgradeable`（V1）
  - `NftAuctionWithOracleUpgradeableV2`（V2，增加修改结束时间 / 取消拍卖功能）
- 目标：
  - 在 **保持 V2 功能和存储不变** 的前提下，升级到 **V3 实现动态手续费**：
    - 根据成交金额折算的 USD 大小，自动选择不同的手续费费率；
    - 将手续费发送到指定的 `feeRecipient` 地址。

---

## 2. V3 合约说明

- 新增文件：`nft/src/NftAuctionWithOracleUpgradeableV3.sol`
- 继承关系：

```text
NftAuctionWithOracleUpgradeable (V1)
  ↳ NftAuctionWithOracleUpgradeableV2 (V2)
    ↳ NftAuctionWithOracleUpgradeableV3 (V3，新增动态手续费)
```

- **V3 新增状态变量**（追加在最后，兼容 UUPS 升级）：

```solidity
address public feeRecipient;      // 手续费接收地址（0 表示不收取）
uint96  public lowFeeBps;        // 低档手续费（bps，万分比）
uint96  public highFeeBps;       // 高档手续费（bps，万分比）
uint256 public feeThresholdUSD;  // 手续费档位阈值（按成交额换算的 USD）
uint256 public constant VERSION_V3 = 3;
```

- **按成交金额动态收费：**
  - 先用 `_getBidUSDValue` 计算当前最高出价对应的 USD 金额 `usdValue`；
  - 如果 `usdValue < feeThresholdUSD` → 使用 `lowFeeBps`；
  - 否则 → 使用 `highFeeBps`；
  - 手续费：`feeAmount = amount * feeBps / 10_000`，卖家实收：`sellerAmount = amount - feeAmount`。

- **结算时自动扣手续费：**
  - 覆盖 `_payoutSeller`，在向卖家转账前，先把 `feeAmount` 转给 `feeRecipient`（ETH 或 ERC20）。

- **主要新增函数：**
  - `initializeV3(address feeRecipient, uint96 lowFeeBps, uint96 highFeeBps, uint256 feeThresholdUSD)`  
    - 使用 `reinitializer(2)`，升级后调用一次完成 V3 初始化。
  - `setFeeParams(...)`：后续可由 owner 调整手续费参数。
  - `quoteFee(uint256 auctionId)`：查询当前拍卖预计手续费、卖家实收和应用的费率。

---

## 3. 升级前检查

在升级到 V3 之前，建议先完成以下检查：

1. **确认当前实现版本**
   - 当前代理应指向 `NftAuctionWithOracleUpgradeableV2`；
   - 可以在脚本或前端中调用 `getVersion()` 确认返回 `2`。
2. **确认没有在使用旧实现合约地址**
   - 外部交互应始终通过 **代理地址** 完成；
   - 任何直接与实现合约（implementation）交互的脚本都需要更新。
3. **备份现有配置**
   - 记录当前使用的价格预言机地址、`stalePriceThreshold`、已有拍卖数据等，以便调试时参考。

## 4. 部署 V3 实现合约

本项目已经提供了完整的 Foundry 脚本，可以直接使用。

### 4.1 全新部署一个 V3 版本的拍卖合约

- 脚本位置：`nft/script/DeployNftAuctionUpgradeableV3.s.sol`
- 功能：
  - 部署 `NftAuctionWithOracleUpgradeableV3` 实现；
  - 部署 `ERC1967Proxy` 并在构造函数中调用 `initialize(ETH/USD 预言机, owner)`；
  - 通过代理调用 `initializeV3` 设置手续费参数；
  - 在控制台打印实现地址、代理地址和手续费配置。

#### 环境变量

在根目录的 `.env` 中配置（示例）：

```env
PRIVATE_KEY=0x...
OWNER_ADDRESS=0x...          # 可选，不填则默认使用 PRIVATE_KEY 对应地址
FEE_RECIPIENT=0x...          # 可选，不填则默认使用 OWNER_ADDRESS
LOW_FEE_BPS=100              # 可选，默认 100 = 1%
HIGH_FEE_BPS=200             # 可选，默认 200 = 2%
FEE_THRESHOLD_USD=1000000000000000000000  # 1_000e18，阈值 1000 USD
SEPOLIA_RPC_URL=...
```

#### 执行部署

```bash
cd nftAuction/nft
forge script script/DeployNftAuctionUpgradeableV3.s.sol \
  --rpc-url $SEPOLIA_RPC_URL \
  --private-key $PRIVATE_KEY \
  --broadcast
```

脚本结束后，会在日志中看到：

- `V3 implementation deployed at: ...`
- `Proxy deployed at: ...`（**后续交互都使用这个地址**）
- 当前手续费参数等信息。

## 5. 使用 ProxyAdmin 升级到 V3

假设你之前已经有一个运行中的代理合约：

- 代理地址：`AUCTION_PROXY`（与之前 V1/V2 交互的地址）

### 5.1 使用脚本一键升级（推荐）

- 脚本位置：`nft/script/UpgradeToV3.s.sol`
- 功能：
  - 部署新的 `NftAuctionWithOracleUpgradeableV3` 实现；
  - 调用代理上的 `upgradeToAndCall(newImplementation, "")` 完成 UUPS 升级；
  - 读取 `owner` 作为默认手续费接收地址；
  - 调用 `initializeV3`（如果是首次升级）或 `setFeeParams`（如果已经初始化过）设置手续费参数。

#### 环境变量

在 `.env` 中补充：

```env
PRIVATE_KEY=0x...
PROXY_ADDRESS=0x...      # 现有拍卖合约的代理地址
FEE_RECIPIENT=0x...      # 可选，不填则默认 owner
LOW_FEE_BPS=100
HIGH_FEE_BPS=200
FEE_THRESHOLD_USD=1000000000000000000000
SEPOLIA_RPC_URL=...
```

#### 执行升级

```bash
cd nftAuction/nft
forge script script/UpgradeToV3.s.sol \
  --rpc-url $SEPOLIA_RPC_URL \
  --private-key $PRIVATE_KEY \
  --broadcast
```

脚本结束后会打印：

- 旧代理地址（不变）；
- 新的 V3 实现合约地址；
- 当前手续费接收地址与费率配置。

### 5.2 手工升级（例如使用 Etherscan）

如果你使用的是 ProxyAdmin 管理 UUPS 升级，也可以手动：

1. 部署 `NftAuctionWithOracleUpgradeableV3` 实现合约；
2. 在 ProxyAdmin 的 `write` 选项卡中调用 `upgrade(proxy, implementation)`；
3. 然后用 owner 账户在代理地址上调用 `initializeV3` 或 `setFeeParams` 设置手续费参数。

## 6. 升级后初始化 V3 手续费参数

升级完成后，代理已经运行 V3 逻辑，但 **手续费参数默认为 0**，需要由 `owner` 调用一次 `initializeV3`：

示例：成交额（USD）小于 1,000 时收 1%，大于等于 1,000 时收 2%：

```solidity
// 通过脚本或前端，以 AUCTION_PROXY 为合约地址、以 owner 身份调用：
NftAuctionWithOracleUpgradeableV3(AUCTION_PROXY).initializeV3(
    FEE_RECIPIENT,   // 手续费接收地址
    100,             // lowFeeBps = 1%
    200,             // highFeeBps = 2%
    1_000e18         // feeThresholdUSD，与 minBidUSD 同单位
);
```

> 注意：`initializeV3` 使用 `reinitializer(2)`，只能成功调用一次；  
> 后续调整可以使用 `setFeeParams(...)`。

## 7. 升级后的验证步骤

1. **版本检查**

```solidity
NftAuctionWithOracleUpgradeableV3(AUCTION_PROXY).getVersionV3(); // 应返回 3
NftAuctionWithOracleUpgradeableV3(AUCTION_PROXY).getVersion();   // 仍返回 2（V2 的版本函数）
```

2. **手续费预估**

- 创建一个测试拍卖并出价；
- 调用：

```solidity
(uint256 feeAmount, uint256 sellerAmount, uint96 feeBps, uint256 usdValue) =
    NftAuctionWithOracleUpgradeableV3(AUCTION_PROXY).quoteFee(auctionId);
```

- 确认：
  - `feeBps` 会根据 `usdValue` 与 `feeThresholdUSD` 的大小选择 `lowFeeBps` 或 `highFeeBps`；
  - `feeAmount + sellerAmount == highestBid`。

3. **实际结算验证**

- 正常流程调用 `endAuction(auctionId)`；
- 确认：
  - 卖家收到 `sellerAmount`；
  - `feeRecipient` 收到 `feeAmount`；
  - 事件 `FeeCharged` 被正确触发。

---

## 8. 回滚与注意事项

- 如果 V3 出现问题，可以用同样的 `ProxyAdmin.upgrade` 再次把实现指回 V2；  
- 升级前后不能改变 `Auction` 结构体和已有状态变量的顺序与类型，否则会导致存储错乱；
- 建议在测试网（如 Sepolia）完成一遍完整流程（创建拍卖 → 出价 → 结算 → 验证手续费）后，再在主网上执行升级。
